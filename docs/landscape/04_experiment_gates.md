# 实验闸门：不以做完代码等同研究通过

## G0：任务和可观测性

固定两个真正不同的反馈目标，逐场景确认语义和缺失；定义目标人群、目标规模、训练预算和最差组约束。没有propensity则不声明IPS/OPE因果结果；没有未来成熟标签则不把unknown当negative。此关失败优先换任务定义，不加模型。

## G1：最小机制

冻结一个模型checkpoint，测多目标完整响应A。比较单分数、pair/batch响应；检测联合margin变化是否仅来自梯度范数/样本长度/流行度。用有限步实际目标损失检验符号。训练序列问题在相同多重集下换序，而非换一批数据。

抽查10–20组候选只是建议的起始检查，不是统计充分样本量。若观察不到可重复的非加性互补，或简单混合即可解释，主线应收窄成优化/分布问题；不继续包装先修兴趣。

## G2：本库已做的CPU实现验证

执行单元测试、10方向数学原型、3种子tiny SFT和3种子分类RL。准确结果见 `results/` 与[验证报告](../VALIDATION.md)。原型训练并未稳定提升测试指标，因此**G2只通过工程/内核，没有通过推荐效果**。

## G3：真实数据小规模适配

从训练日志抽有限规模、保留selection/calibration/test，用本地预训练模型做共享反馈头SFT。先验证baseline本身能学会目标，再比较同初始化、同候选池与同token的uniform/scalar/frontier/atoms。低成本危险基线优先。HF脚本提供入口，但本轮未安装依赖/加载权重，需在目标环境先做单卡smoke。

一个可接受设计是2反馈、1模型家族、2数据场景，冻结SID/文本版本。不要为了赶规模同时加入新tokenizer、更多训练数据和RL。误差界需要独立校准；test用于最后评估，不用于决定是否把atoms写进标题。

## G4：完整机制和基线

在已通过G3后加入MoRec/DEALRec/GORACS等官方或忠实复现；开展RL必须包含MiniRec，对解码必须包含AtSpeed/SpecGR相应任务。不同方法loss/reward与生成后处理对齐，报告无法完全对齐之处，不把论文表格数值当本机同条件对照。

做配对补回、替换补回、时序互换、权重变化、关闭观测校正和控制共享因素等反证。若atoms无效删掉；若时序无效主线保持静态，不能用另一个新命名掩盖。

## G5：科学/用户外部验证

科学组合做盲评、真实schema/执行记录；前驱体路线需独立计算/实验。图探索在模拟器通过后仍需真实日志支持/前瞻反馈。达不到这层只声称benchmark或模拟环境效果。

## Stop rules

训练集或选择集提高而test持续下降；获取成本计入后优势消失；单次proxy得分无法跨时段预测；更多数据/简单分层即可解释；所谓安全性只来自同源LLM judge；真实业务目标的损失被Recall@K上涨掩盖。任何一项都应停止相应claim，不必停止整个项目。
