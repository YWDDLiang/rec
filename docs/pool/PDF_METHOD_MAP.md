# PDF方法对照：保留什么，澄清什么，新增什么

核验对象：用户提供的 `gradient atom(1).pdf`，16页。本文不把此前的在线优化器短窗确认框架冒充PDF的方法。本轮默认路线是离线数据选择；上轮的在线工具可以另作诊断，不能混用结果。

## 1. 方法事实与代码对应

| PDF位置 | PDF内容 | 本轮实现及边界 |
|---|---|---|
| pp.1–3 | 固定checkpoint，response-only SFT，逐样本LoRA梯度，固定signed hash，512维，L2方向，64个atom，OMP最多4个非零系数 | `sft.extract` 保存所有requires_grad参数的梯度投影；`geometry.fit_dictionary` 对方向做MiniBatchDictionaryLearning和signed OMP。LoRA是默认HF设置，不把完整参数模型说成原PDF复现 |
| pp.4–5 | 一个样本通常同时激活多个atom；dominant标签只是摘要；符号不能随意丢弃 | `geometry.coordinates` 使用完整带符号code；dominant规则单独作为对照 |
| pp.6–9 | 需要真实response；假设性response的梯度不能当真实行为；probe不更新权重；模板、LoRA初始化和参数顺序重要 | 相同Record编码供probe与训练；禁止test/audit/tune参与提取；保存manifest、checkpoint说明、投影hash、每个缓存文件hash。测试确认probe不改参数、模式与原梯度 |
| pp.10–12 | 同时保留raw、unit与norm；重构误差不等于脏数据；维数和atom数应消融 | 保存raw/unit/full-norm/loss；保留32/64/128、2/4/8、256/512/1024的实验配置建议，不假称64最优 |
| pp.13–14 | dominant桶超过800再筛；用户理解保留；高系数与中间loss分层采样；min50只作截断后的修补；完整code去近邻、medoid、定向回填 | `baselines.pdf_rule_reference` 是可执行的文字规则解释，不是原脚本；新增选择器是明确标记的预算化扩展。原文没有给出的middle loss分位数暂用可配置0.2/0.8，必须消融 |
| pp.14–15 | 掉能力时从被移除的训练池定向回填；对照随机回填；记录重复和token | `refill` 固定task×domain与实际response-token数进行交换；保留原来源配额与保护约束；同root不同任务不自动判重复 |
| p.16 | 局部梯度几何不能替代训练后的真实推荐验证 | 训练线路测试与真实推荐结果分开；本轮没有真实预训练模型实验 |

## 2. 不能省略的原始观察

PDF对41,127条样本的诊断给出dominant share均值40.75%，达到0.7的样本只有0.47%。这支持“不要只看最大atom”的工程决定，但不是“完整code选样一定提高推荐”的证据。业务任务同时包括视频/广告/商品/直播推荐、用户理解、物料映射、通用推理，因而适合寻找同一更新方向在不同训练角色中的重复和互补。

PDF还明确指出probe添加了 `### Task {task_type}`，正式训练模板并不完全一样。新实验必须先用原生编码器导出相同token与mask。不得在研究中重新引入这个不一致，再把任务可分性解释成有意义的行为分解。

## 3. 新增的代数修正：code空间不自动等于梯度空间

PDF建议完整code余弦作为定向回填方法之一。本轮把“直接code余弦”和“字典Gram修正余弦”并列保留，不把后者写成PDF已有结论。

当X≈CD时，重构梯度的内积是 `C_i (D Dᵀ) C_jᵀ`。只有D的行正交时才等于 `C_i C_jᵀ`。因此，两个code可以欧氏正交，却对应十分接近的重构梯度。此项是线性代数一致性修正，不是一个新的推荐有效性定理。

## 4. 新增的预算化扩展，不替代原始规则对照

原规则的800/50是计数阈值，无法自动处理不同数据池大小、长短response、不同任务稀缺程度。新增实现把admission token预算、任务配额、provenance cap写入显式约束，并提供完整code的logdet覆盖代理。logdet是标准设计目标，非原创数学；它用于提出候选，不被称为真实用户信息增益。

方向覆盖无法区分 `g` 与 `-g` 的好坏。因此，带符号参考对齐与定向回填必须独立评估；没有验证依据时不主动把稀有方向当成好数据。受控实验已验证“稀有但错标签”能使纯覆盖选择变差。

## 5. 原规则复现时的四个细节

字符阈值是原始文本字符，不是response token数；合法SID可以很短，不应被通用字符规则误删。用户理解的全部保留可能使桶超过800，不能为了漂亮的保留率破坏这个条件。小桶不足50不应复制到50。同一个root下的 `description→ID` 与 `ID→description` 是不同监督方向，不应因root相同就全部删到一条。

建议将“原始规则逐字实现”“原规则的文字澄清版”“预算化完整code版”分成三个清楚命名的实验。当前只拥有PDF文字而非原atom_dedup脚本，故代码中的 `pdf_rule_reference` 只能叫第二种。
