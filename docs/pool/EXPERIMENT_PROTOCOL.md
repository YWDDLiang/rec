# 实验预注册建议：验证“数据富余时选择的边际价值”

本文件是待执行方案，不是已完成真实实验。每个实验先锁定成功/失败判据和seed，再开始训练。旧E001–E006保留原始负结果；不得替换其表格或用本轮toy结果补齐真实指标。

## 1. 要区分的变量

| 变量 | 可执行的干预 | 不能混淆的解释 |
|---|---|---|
| 独立root数量U | 用固定hash顺序形成嵌套训练root池，全部派生任务继承root | 不能只扩同一历史的提示词就称独立数据增加 |
| 每root派生量A | 增加实质任务/约束，或另做同义模板重复 | 实质能力丰富与表面复述分开 |
| 领域/任务数M | 固定总root数时增加来源；另做来源自然规模不均衡 | 不能同时增加数据量后把收益全归多场景 |
| 准入支持B_select | 决定允许遍历的候选子集，报告每来源实际token | 与真正优化器暴露B_train不同 |
| 训练暴露B_train | 相同response-token总量、近似相同输入token/步数 | 减少样本后多训几遍不是免费 |
| 选择计算C_select | probe、字典、检索、回填、额外验证均计时 | 少训20%不意味着总成本降20% |

## 2. 建议先跑的最小矩阵

先选择LC-Rec风格丰富SFT或RecLM-gen中的一个，不同时开四个数据工程项目。主骨干Qwen3-1.7B、固定warm checkpoint、LoRA rank8；本包默认无dropout的稳定probe，正式训练是否保留dropout必须所有方法相同并记录。

第一阶段只做五组：全池同预算、task×domain×长度分层随机、PDF文字规则、完整raw梯度、完整code/Gram版本。每组相同训练预算与初始化，先两个开发seed检查稳定性，不作最终显著性结论。

候选池富余度分为0.5、1、4、16倍的参考训练监督量；这是设计坐标，不是要求任何给定数据都恰好满足这个比值。实际填表应写真实root数、record数、token数。准入比率不要每档都强制保留20%；当所有候选都可容纳且质量合格时保留全池。主训练暴露独立锁定。

第二阶段再增加原生DEALRec、GORACS、LESS和简单语义/聚类对照，扩大到3个以上训练seed，确认主效应后用第二个骨干/场景。没有第一阶段信号时先停在机制诊断，不再跑复杂RL。

## 3. 四组能够否证主张的实验

### A. 丰富池是否真的提供不同监督？

做自然更多root、不同任务派生、纯模板重复三个分开扩池。若收益只在人工制造的重复里出现，论文只能声称抗重复，不能推广到自然数据富余。若普通root去重与任务均衡已经解释收益，不继续把atoms列为主贡献。

### B. 单标签是否丢失关键结构？

保持相同输入梯度，比较dominant分桶、KMeans、完整C欧氏、完整C的Gram几何以及原始投影梯度。不要用更大的字典/更多query使atoms占预算优势。若Gram仅改变可视化而不改变独立响应/训练效果，作为正确性细节，而非大贡献。

### C. 选择是否牺牲少量关键能力？

预先登记用户理解、负约束、稀有类别等必须报告的任务，使用不改变任务配额的消融。另做允许任务调配的工程版本，将二者区分。不能因为稀有任务使macro难看而取消该任务。也不能因为一个来源稀有就完全不看标签质量。

### D. 回填是否具有目标特异性？

只用SELECT参考提名，从removed TRAIN pool交换；设0、500、1000、1500为大池候选网格，小池按池大小预注册缩放。实际交换数可能小于请求数。随机组严格匹配任务、domain、长度、实际交换数。测试前最多确定轮数，避免无限adaptive validation。

## 4. 两种公平性主表

**等训练预算表：** 完全相同主模型、原生SID目录/文本输出、初始化、训练token/steps、数据生成teacher、generation temperature及排序协议。允许选择器额外计算，但全部单列。此表回答选出的数据是否更好。

**等总计算表：** 给uniform额外训练时间，使总GPU时或可复核FLOPs/墙钟口径匹配。字典用一个小probe拟合后用于更大候选池的方案，也应支付所有逐样本反传。此表回答是否值得部署。跨不同型号GPU的墙钟不可直接相加比较。

额外报告全池一遍/多遍的学习曲线，而不是只和很弱的随机20%比较。B_train不足以遍历全池时称“all-pool sampler”；B_train≥全池token且执行一次才称“full epoch”。

## 5. 数据与统计协议

先拆分原始交互/查询root，后做多任务派生；reference、tune、audit、test职责分开。使用同一个用户多次查询时按用户聚合区间；训练seed变异另行统计，不能以大量用户bootstrap替代训练seed。已多次用于调参的audit应改名development，不再称未见测试。

token budget只数labels!=-100且经过causal shift仍被预测的token。日志同时记录输入token、optimizer steps、packing规则、梯度累积、学习率、重复occurrence。不同任务长度造成的步数差不能忽略；尽量用task×domain×长度桶匹配，余量公开，不通过截断合法SID凑精确预算。

构造的历史摘要可以验证是否符合历史，但不是人类偏好真值。由目标评论生成的意图用于独立意图检索，不可泄漏到next-item评测。未观测item不是确认负反馈。KuaiSAR匿名文本不改写成真实自然语言。

## 6. 显著性与最小效果

主指标只预先选一个主ranking终点与一组约束/能力非劣终点。共同任务不能依靠“总均值上涨”掩盖某项严重下降。对多次算法/预算搜索明确控制开发阶段探索范围；最终用冻结配置独立测试。

最小有意义的效果阈值应由应用和基线方差确定，不先凭空保证1%/5%。先根据开发seed和配对用户差异估计功效，再决定确认样本量。报告均值、训练seed标准差、配对用户区间以及所有失败配置，不只给best seed。

## 7. 进入论文主线的门槛

第一门槛：相同编码/optimizer/数据池下，选择确实改变实际消费的记录，预算与配额日志正确。

第二门槛：丰富自然池里，至少一个目标获得可复现改善且必要能力非劣；不只出现toy或人工重复收益。

第三门槛：胜过PDF原规则、来源再平衡、raw gradient、KMeans以及至少两种直接相关外部算法；否则缩小贡献，不换名字逃避强基线。

第四门槛：在第二个语义结构不同的任务或第二骨干上确认。跨模型复用的是“方法”，不是原子编号和参数坐标。

门槛未通过时也有清楚结论：数据丰富不等于应当筛；几何覆盖不等于高价值监督；atoms可能仅是可视化/诊断工具。不能预先承诺WWW接受或排名必涨。
