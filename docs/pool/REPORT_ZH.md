# 从“数据越多越筛”到“预算条件下的有效监督选择”

日期：2026-09-09。更新目标：`YWDDLiang/rec`与`YWDDLiang/Research/llm4rec`。当前交付为可自行push的新增目录，不改写远端、不覆盖原实验归档。

## 一、结论

用户的直觉值得研究，但应写成一个可检验的条件命题：**当训练预算有限、候选池中存在大量重复或低增益监督、关键能力又分布不均时，数据选择可能比均匀消费所有可用数据更有效。** 小数据时随意删样本可能损失信息；大数据时也可能由于标签质量、参考偏差或额外选择成本而失败。

不再将任务限定为OneReason。优先推荐两个能自然形成丰富SFT池的场景：LC-Rec/MiniOneRec式多角色生成推荐，以及RecLM-gen式可控推荐。KuaiSAR用于真实跨服务结构的外部验证，但其query/caption已经匿名化，不适合作为“LLM理解原始搜索文本”的主证据。

方法主线仍遵循用户PDF：固定checkpoint的response-only梯度，固定投影，稀疏atoms，来源/稀有能力保护下的筛选，再从removed训练池定向回填。在线AdamW双分支短训不是默认主方法；复杂流程不能替代数据池和基线的正确选择。

## 二、为什么此前小规模实验不足以否定或证明新假设

旧E006已经是Office/Industrial两域真实LLM实验，原子方法未建立优势，部分开发指标下降。因此不能说“只要改成多场景就会好”。其候选任务角色、样本冗余、梯度表示与验证噪声都可能影响结果，但这些只是解释候选，尚未逐一归因。

新的研究不是在同一失败配方上扩大N，而是重新明确比较对象：在丰富的多角色SFT池中，热门/容易监督是否挤占了有限训练暴露，来源配比是否过于粗糙，完整行为code能否识别真正可以少训的部分。数据规模是一个实验轴，不是有效性的证明。

## 三、研究问题与贡献候选

建议题目：**Budget-Conditioned Behavioral Data Selection for Multi-Task LLM Recommendation**。这个工作标题不是已有效果声明，也不是在承诺一个新算法名。

研究问题：给定固定的预训练LLM、推荐目录、多角色候选SFT池和训练预算，如何分配训练机会，使重复监督的边际收益下降时不继续过度训练它，同时保住少量但必要的推荐和指令能力？

可争取的贡献一是推荐领域的监督冗余刻画：区分独立交互root、同root不同任务、同任务复述和实际训练出现次数，检验哪一种丰富度真正改变选择收益。仅统计行数或dominant atom频次无法完成此任务。

可争取的贡献二是来源约束下的完整code选择与目标特异性回填：保留稀疏组合、符号、字典真实度量以及来源配额，不用等量补齐所有atom。数学修正本身不是大贡献；只有它相对于完整raw梯度、普通KMeans、DEALRec/GORACS/LESS等强对照带来可复现收益，才可支持方法贡献。

可争取的贡献三是预算区域与失败边界：明确在哪些候选池/训练预算/标签质量组合下全池更好，在哪些情况下选择有效，避免一刀切保留20%。这类区域思想已有相关研究先例，必须落到推荐特有的多任务监督与必要能力保护，而不能只换benchmark。[S18–S21]

## 四、比原始PDF规则更严谨的几处深化

第一，800条的桶阈值变成预算与来源稀缺条件。池小、标签合格、预算容得下时不强制筛；池大时先看来源内实际重复和目标差异，不按atom数量机械均衡。用户任务保护来自业务/任务要求，不由无监督字典自行决定。

第二，完整code不等于普通code距离。字典非正交时重构梯度内积含 `D Dᵀ`；本轮同时保留直接code和Gram修正对照。完整梯度范数、投影raw和unit分别保存，不能从unit缓存假造缺失幅度。

第三，同root不必都冗余。ID到文本和文本到ID可以形成不同监督；只有明确的provenance关系才限制重复，不能把不同用户看起来相同的历史全部当一个观测。

第四，定向回填必须是训练池交换。它不读取最终测试；同来源、同实际response长度、有限次数，匹配随机回填。代码返回实际交换数，不会为了凑满1500破坏保护任务。

第五，选出来的支持集与实际训练曝光分开。数据少了但重复四遍，必须记录四倍occurrence；全池太大只抽一部分训练，也不能声称已经看过全部记录。新增训练器直接消费明确索引计划，防止选样文件生成了但训练仍读旧数据。

## 五、初步证据：通过什么，尚未通过什么

本轮新增单元测试56项通过；与原始基础110项的联合结果以最终VALIDATION记录为准。另有80个受控线性回归训练运行，以及实际随机初始化小型自回归模型的probe→字典→选择→SFT流水线。这里没有任何真实预训练LLM或实际推荐benchmark的结果。

受控实验表明：稀缺且预算容得下时，规则可原样保留全部数据；丰富但单一方向极度重复时，方向覆盖能改善构造测试误差；稀有方向全部含错误标签时，纯覆盖明显变差。带目标符号的信息可以避免其中部分错误，但它使用的是构造环境的精确参考，不能直接外推到噪声真实参考。

完整code和原始梯度在同一理想方向结构中可能完全等价。当前没有证明字典学习带来额外推荐收益，不把数值正确性当成论文有效性。

## 六、建议的执行顺序

先用一个非OneReason主场景完成原生训练复核，锁定共同warm checkpoint、目录、模板和loss；用相同原始训练root构造嵌套候选池；比较全池同预算、任务/长度随机、PDF原规则、raw与完整code；出现真实信号后再接DEALRec/GORACS/LESS、扩展第二骨干与RecLM-gen场景。

先做SFT。RL、PageRank探索和科学推荐新数据集暂不混进同一论文。科学背景最有价值的迁移是“先规定哪些能力不能被平均指标吞掉”，而不是额外叠加一个看似更复杂的模块。
